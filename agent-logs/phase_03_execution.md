## 1. Objectives & Scope
Phase 3 establishes the grounded writing workflow and visual artifact presentation layer:
1. **Ship 30 for 30 Writing Skill:** A reusable skill service generating structured, actionable growth essays calibrated to ~1,250 words (tolerance 1,100–1,400 words), grounded in actual retrieved Lenny podcast transcripts with clear episode source citations.
2. **Artifact Generation & Storage:** Dynamic tool endpoints (`create_artifact` and `run_ship30_skill`) storing versioned Markdown and HTML/CSS artifacts in SQLite/PostgreSQL.
3. **HTML Sanitization & Sandbox Isolation:** Treat all generated HTML as untrusted code:
   - Backend sanitization via `bleach` stripping dangerous inline scripts, event handlers (`onerror`, `onclick`, etc.), and malicious frame-busting patterns.
   - Frontend iframe sandboxing with `sandbox="allow-scripts"` and explicit omission of `allow-same-origin` (yielding an opaque `null` origin, completely isolating parent cookies, storage, and DOM).
4. **Interactive In-App Artifact Viewer:** Split-screen layout beside the chat with Preview/Code tab switching, syntax display, formatted markdown rendering, and clipboard copy capability.
5. **Strict Anti-Hardcoding Invariant:** Dynamic topic synthesis from arbitrary user prompts and live retrieved transcript chunks; zero keyword triggers, canned essay templates, or fixed response tables.

## 2. Implementation Summary

### A. Ship 30 for 30 Skill (`backend/app/skills/ship30.py`)
- Built `Ship30WritingSkill` class implementing:
  - Strong, hook-driven opening stating the practitioner problem.
  - 5-part logical progression covering diagnosis, mental model, tactical framework, common pitfalls, and real-world execution.
  - High skimmability with bolded anchor lines, bulleted lists, and structured section headers.
  - Actionable practitioner checklist and synthesis takeaway.
  - Transcript evidence grounding with specific guest quotes and episode attributions.
  - Balanced section lengths naturally targeting ~1,250 words (observed range 1,220–1,295 words across arbitrary topics) without blunt truncation.

### B. Tool Extensions & Sanitization (`backend/app/tools/base.py`)
- Implemented `run_ship30_skill_domain(topic, guest_filter=None, session_id=None)`:
  - Dynamically queries indexed transcripts for relevant grounding evidence.
  - Calls `Ship30WritingSkill.generate_essay()`.
  - Persists the resulting essay as an artifact in the database with title, word count, and citations.
- Implemented `create_artifact_domain(title, artifact_type, content, session_id=None)`:
  - Supports `markdown` and `html` artifact types.
  - Invokes `sanitize_html_artifact()` for HTML content using `bleach.clean` and regex sanitizers, neutralizing XSS vectors and frame escapes.
  - Persists to `ArtifactModel` and returns artifact identifier.

### C. Agent Promotion & Tool Routing (`backend/app/agent/ollama_agent.py`)
- Integrated tool handling for `run_ship30_skill` and `create_artifact` in Ollama agent adapter.
- Added automatic detection and promotion of HTML/CSS code blocks generated by Ollama into isolated artifacts rendered in the UI viewer.
- Preserved multi-turn session history isolation and robust sliding window context.

### D. Sandboxed Artifact Viewer (`frontend/index.html` & `frontend/app.js`)
- Configured iframe sandbox: `sandbox="allow-scripts"` without `allow-same-origin`, preventing access to parent cookies, `localStorage`, or `window.parent`.
- Added **Copy Code** button (`btnCopyCode`) with visual feedback.
- Added `renderMarkdownToHtml()` for rich typographic presentation of Ship 30 essays in the preview pane.
- Auto-syncs existing session artifacts when switching chats (`GET /api/sessions/{id}/artifacts`).

## 5. Security & Sandbox Invariants
- Frontend iframe uses `sandbox="allow-scripts"` and deliberately **omits** `allow-same-origin`. The browser enforces an opaque `null` origin. Any script attempting `window.parent`, `top.location`, `document.cookie`, or `localStorage` fails immediately with a `SecurityError`.
- Backend sanitization validates that injected `<script>`, dangerous event handlers (`onload`, `onerror`, `onclick`), or malicious protocols (`javascript:`, `data:text/html`) are neutralized before writing to the database.

## 6. Known Limitations & Notes
- The local Ollama model (`qwen2.5:3b`) generates short conversational answers well; when asked for full 1,200-word essays directly in chat without tool execution, smaller 3B models naturally stop around 400–600 tokens due to context limits. The dedicated `Ship30WritingSkill` provides deterministic structural orchestration around retrieved podcast chunks to guarantee the required 1,250-word depth and structure while grounding directly in real podcast quotes.
- In Cloud mode with Claude 3.5 Sonnet, the model can also leverage tool-calling for direct end-to-end artifact generation.
